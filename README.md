# План разработки проекта: AI Localization QA

## 1. Описание проекта

Разработать веб-приложение для автоматического поиска ошибок в казахской и узбекской локализации мобильных игр.

Система должна анализировать существующие переводы относительно английского оригинала, находить ошибки, объяснять их и предлагать исправленные варианты.

Особенность проекта — возможность проверки исправлений носителями казахского и узбекского языков.

Это не обычный переводчик, а инструмент контроля качества игровой локализации (Localization QA).

## 2. Основная концепция

Пользователь загружает файл локализации мобильной игры.

Например:
- English: Start Game
- Kazakh: Ойынды бастау
- Uzbek: O'yinni boshlash

AI анализирует переводы и:
1. Находит грамматические ошибки.
2. Находит орфографические ошибки.
3. Проверяет соответствие оригинальному смыслу.
4. Проверяет соответствие игровому контексту.
5. Проверяет единообразие терминологии.
6. Находит неестественные выражения.
7. Проверяет переменные и placeholders.
8. Проверяет длину текста для элементов интерфейса.
9. Предлагает исправленные варианты.
10. Объясняет причины каждого замечания.

Важно: AI не должен выдавать сомнительные исправления за гарантированно правильные.

## 3. Технологический стек

Основные технологии:

- Python — основной язык программирования.
- Django — backend и API.
- PostgreSQL — база данных.
- HTML — структура интерфейса.
- CSS — дизайн.
- JavaScript — интерактивность.
- GPT API или Gemini API — AI-анализ.
- Git и GitHub — контроль версий.

Дополнительные библиотеки:
- pandas — работа с таблицами.
- json — обработка JSON.
- xml.etree.ElementTree — обработка XML.
- python-dotenv — переменные окружения.

Не использовать React на первом этапе. Не создавать отдельное desktop- или мобильное приложение.

## 4. Архитектура

Web Interface:
- загрузка файлов;
- отображение результатов;
- редактирование переводов;
- подтверждение исправлений;
- экспорт.

Django Backend:
- обработка запросов;
- авторизация;
- управление проектами;
- обработка локализаций;
- взаимодействие с AI API.

PostgreSQL:
- пользователи;
- проекты;
- оригинальные строки;
- переводы;
- найденные ошибки;
- исправления;
- история проверки носителями.

AI Module:
- анализ оригинала и переводов;
- поиск проблем;
- предложение исправлений;
- объяснение ошибок;
- оценка уверенности.

## 5. План разработки по этапам

### Этап 1. Подготовка проекта

- Создать GitHub-репозиторий.
- Настроить Python virtual environment.
- Установить Django.
- Создать Django-проект.
- Настроить PostgreSQL.
- Создать базовую структуру приложения.

### Этап 2. Обработка файлов

Первоначально поддерживать только CSV и JSON.

Реализовать:
- загрузку файлов;
- проверку формата;
- чтение английского оригинала;
- чтение казахского перевода;
- чтение узбекского перевода;
- отображение строк;
- проверку наличия пустых значений.

Не изменять оригинальные файлы без подтверждения пользователя.

### Этап 3. AI-анализатор

Подключить GPT API или Gemini API.

Разработать модуль, который получает:
- английский оригинал;
- казахский перевод;
- узбекский перевод;
- контекст игры;
- информацию о персонажах и терминологии, если она доступна.

AI должен возвращать структурированный результат:

- language;
- original_text;
- current_translation;
- error_type;
- error_description;
- suggested_translation;
- confidence;
- requires_human_review.

Типы ошибок:
- Grammar;
- Spelling;
- Meaning;
- Context;
- Terminology;
- Tone;
- Placeholder;
- Length.

AI должен различать настоящие ошибки и стилистические рекомендации.

### Этап 4. Web Interface

Создать интерфейс:
- главная страница;
- панель проектов;
- страница загрузки локализации;
- таблица переводов;
- страница результатов анализа.

В таблице отображать:
- оригинальный английский текст;
- текущий перевод;
- предложенный перевод;
- тип ошибки;
- объяснение;
- уверенность AI;
- статус проверки.

Добавить фильтрацию по языку и типу ошибки.

### Этап 5. Human Review

Реализовать систему проверки носителями.

Статусы:
- Pending;
- Approved;
- Rejected;
- Edited.

Проверяющий должен иметь возможность:
- посмотреть оригинал;
- посмотреть текущий перевод;
- посмотреть предложение AI;
- принять исправление;
- отклонить его;
- предложить собственный вариант;
- оставить комментарий.

Сохранять историю изменений и информацию о проверяющем.

Не утверждать, что перевод проверен носителем, пока реальный человек не подтвердил его.

### Этап 6. Экспорт

Добавить:
- экспорт CSV;
- экспорт JSON;
- сохранение оригинальной структуры;
- возможность экспортировать только подтверждённые исправления;
- сохранение placeholders без изменений.

### Этап 7. Безопасность

Реализовать:
- HTTPS;
- Django Authentication;
- защиту API-ключей;
- проверку загружаемых файлов;
- ограничения размера файлов;
- изоляцию пользовательских проектов;
- резервное копирование PostgreSQL;
- политику хранения и удаления файлов.

### Этап 8. GitHub Integration

Это будущая функция, не часть первого MVP.

Планируемая функциональность:
- подключение GitHub-репозитория;
- обнаружение изменённых файлов локализации;
- автоматический анализ изменений;
- создание Pull Request с исправлениями;
- возможность принять или отклонить предложенные изменения.

## 6. MVP — первая рабочая версия

Не пытаться реализовать всё сразу.

Первая версия должна включать только:

1. Загрузку CSV и JSON.
2. Чтение английского, казахского и узбекского текстов.
3. AI-анализ переводов.
4. Обнаружение ошибок.
5. Предложение исправлений.
6. Объяснение проблем.
7. Простой веб-интерфейс.
8. Экспорт исправленного файла.

Авторизацию, систему носителей и GitHub-интеграцию можно добавить позже.

## 7. Правила разработки

Работать последовательно, небольшими этапами.

- Не создавать весь проект одним большим блоком кода.
- Сначала объяснять архитектуру каждого модуля.
- Затем давать конкретные инструкции по реализации.
- Объяснять незнакомые технологии.
- Проверять код после каждого этапа.
- Не переходить к следующему этапу, пока предыдущий не работает.
- Использовать Git для сохранения стабильных версий.
- Не придумывать несуществующие API и методы.
- При использовании внешних библиотек проверять актуальную документацию.
- Избегать ненужной сложности и преждевременной оптимизации.

## 9. Первая задача

Начни с анализа архитектуры MVP.

Объясни:
1. Как будет организована структура Django-проекта.
2. Какие приложения Django необходимо создать.
3. Какие модели базы данных понадобятся.
4. Как модули будут взаимодействовать друг с другом.
5. Какие технологии нужно установить.

Не начинай сразу писать весь код. Сначала согласуй архитектуру и предложи последовательность реализации.
